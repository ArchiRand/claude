# Гейт планирования разработки

Перед неочевидной или многошаговой разработкой — сначала спланируй, а не сразу пиши код. Этот скилл запускает и держит цепочку `brainstorming → writing-plans → executing-plans`.

## Приоритет инструкций

1. **Явные инструкции пользователя** (CLAUDE.md, прямые запросы) — высший приоритет
2. **Этот скилл и цепочка планирования** — переопределяют поведение по умолчанию там где конфликтуют
3. **Поведение по умолчанию** — низший приоритет

## Обязательный порядок работы над фичей

```
brainstorming → [спек сохранён в docs/specs/] → writing-plans → executing-plans (с ревью через субагента code-reviewer)
```

<HARD-RULES>
1. **Спек обязателен.** brainstorming ВСЕГДА завершается записью спека в `docs/specs/YYYY-MM-DD-<тема>-design.md` и одобрением пользователя. Переход к writing-plans без спека — запрещён.

2. **Ревью — только через субагента.** После завершения реализации запускай субагент `code-reviewer` через tool `Agent`. Если в проекте есть свой ревьюер в `.claude/agents/` — бери его. Ревью в текущем контексте не делаем: смысл в изоляции, чтобы чтение файлов не засоряло контекст исполнителя.

3. **Порядок нарушать нельзя.** Нельзя пропускать шаги даже если задача кажется простой. Исключение: однострочные правки без логики (опечатки, переименование, правка конфига) — для них brainstorming и writing-plans не нужны, достаточно сразу executing-plans или прямого редактирования.
</HARD-RULES>

## Передача между этапами

| Ситуация | Скилл |
|----------|-------|
| Есть идея/задача, нужно спроектировать реализацию | **brainstorming** |
| Спек готов, нужен план реализации | **writing-plans** |
| План готов, нужно выполнить | **executing-plans** |
| Нужно передать этап в новый чистый контекст | **next-stage-prompt** |

## Когда НЕ применять этот гейт

- Однострочные правки без логики (опечатка, переименование, правка конфига) — правь напрямую
- Баг или неожиданное поведение — используй `systematic-debugging` напрямую
- Коммит или вопрос без изменения кода — соответствующие скиллы (`commit-writer`, `commit-and-changes-writer`) матчатся сами по себе, гейт планирования им не нужен
- Код-ревью — субагент `code-reviewer`, гейт ему тоже не нужен
