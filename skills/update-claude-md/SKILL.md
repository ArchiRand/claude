Ты — технический писатель. Задача: привести `CLAUDE.local.md` в соответствие с реальным состоянием кодовой базы. `CLAUDE.local.md` — это приватный контекст для AI-агента (не для людей): он должен быть точным, кратким и актуальным.

Контекст проекта: Java-монолит, пользователь работает в отдельном модуле (`klone-mobile-server`). Основная документация — в `CLAUDE.local.md`, общие правила — в `CLAUDE.md` и `.claude/rules/*.md`. Не дублируй то, что уже есть в `CLAUDE.md`.

## Алгоритм работы

### Шаг 1: Прочитать текущий CLAUDE.local.md

Прочитай `CLAUDE.local.md` целиком. Выпиши:
- Какие разделы есть.
- Конкретные утверждения об архитектуре, пакетах, аннотациях, механизмах.
- Упомянутые пути к директориям и Java-пакетам.
- Иерархии классов (таблицы Item → Super и т.д.).
- Ссылки на скиллы (`/skill-name`).

### Шаг 2: Проверить каждое утверждение в коде

Источники истины для Java-монолита:

- **Структура модулей** — корневой `settings.gradle.kts` (или `.groovy`), список подпроектов.
- **Зависимости и стек** — `build.gradle.kts` основного модуля: `dependencies {}`, `java { toolchain {} }`.
- **Java-пакеты** — `find src/com -maxdepth 5 -type d`: какие пакеты реально существуют.
- **Конкретный класс или аннотация** — `grep -r "class ClassName\|@AnnotationName" src/` чтобы убедиться что класс существует и находится в правильном пакете.
- **Иерархия классов** (таблицы Item → Super) — `grep -r "extends OfferItem\|extends OfferSuper" src/` и аналогично для других базовых классов. Сверяй каждую строку таблицы.
- **XML-конфиг и ресурсы** — `find . -name "*.xml" -path "*/resources/*"` для проверки групп (`products_offers`, `webshop_visible` и т.д.).
- **Gradle-команды** — `Makefile`, `Rakefile`, `mbuild.yml` если есть; иначе проверяй задачи через `./gradlew tasks --all | grep -E "local-server|resources-ide|validateItems"`.
- **Рабочие зоны** (read/write модули) — `settings.gradle.kts` + `ls` корня репозитория: убедись что перечисленные директории существуют.

Не хардкодь пути — каждый раз определяй из текущего состояния.

### Шаг 3: Выявить расхождения

По каждому разделу CLAUDE.local.md фиксируй:
- **Устарело**: пакет, класс, аннотация, команда упомянуты в CLAUDE.local.md, но не найдены в коде.
- **Неверно**: описано не так, как реально работает (не тот пакет, не те методы, неверная иерархия).
- **Пропущено**: есть в коде, отсутствует в CLAUDE.local.md — добавлять только если агент без этого сделает ошибку или будет переспрашивать.
- **Дублирует CLAUDE.md**: уже есть в общем файле — можно убрать.

Критерий важности для добавления: информация нужна агенту чтобы не ошибиться в архитектурном решении, не нарушить паттерн DI/CDI, не создать дублирующий механизм, не трогать read-only модули. Не добавляй всё подряд.

### Шаг 4: Показать список изменений

Перед правкой покажи пользователю список:

```
УДАЛИТЬ:
- [раздел/строка]: причина (класс не найден / пакет переехал / ...)

ОБНОВИТЬ:
- [раздел]: что устарело → что актуально

ДОБАВИТЬ:
- [раздел]: что и зачем (почему агент без этого ошибётся)

ДУБЛИРУЕТ CLAUDE.md (вынести/удалить):
- [раздел]: уже описано там
```

Дождись подтверждения — или пропусти этот шаг если пользователь сказал «просто обнови».

### Шаг 5: Применить изменения

Правь `CLAUDE.local.md` через Edit tool точечно, не переписывая весь файл целиком.

Принципы:
- Сохраняй структуру разделов если она логична.
- Сохраняй инструкции по поведению агента и ссылки на скиллы.
- Убирай капитан-очевидность — то, что видно из самого кода или стандартно для Java.
- Убирай дублирование с `CLAUDE.md` и `.claude/rules/*.md`.
- Иерархии классов (таблицы): обновляй строку за строкой по результатам grep — не удаляй строку без проверки.
- Рабочие зоны (read/write): обновляй если добавились или удалились модули.
- Gradle-команды: проверяй через `./gradlew tasks` перед обновлением.

## Что не трогать

- Инструкции по поведению агента (рабочие зоны, read-only ограничения).
- Ссылки на скиллы (`/skill-name`) — они живут отдельно, не выводимы из кода.
- Бизнес-контекст и причины архитектурных решений (почему CDI, почему Hazelcast, хотфиксы типа KM-2637).
- Неочевидные ограничения и подводные камни — именно за этим и нужен CLAUDE.local.md.
