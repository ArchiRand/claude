# Graphify для klone-mobile — подключение, настройка, запуск

Кастомный граф знаний по 6 путям, в которых реально ведётся работа (основной —
`klone-mobile-server`). Не покрывает весь репозиторий (114GB — штатный
`/graphify .` на нём не работает, `detect()` зависает на сканировании дерева).

## 1. Требования

- CLI `graphify` (пакет `graphifyy`). Установка:
  ```bash
  uv tool install graphifyy
  ```
  Если `uv` нет — `pip install graphifyy` тоже подойдёт.
- Python-интерпретатор с установленным `graphify` определяется автоматически
  и кэшируется в `graphify-out/.graphify_python` — руками ничего настраивать
  не нужно, включая свежий клон, где этого файла ещё нет.
- API-ключ **не требуется**. graphify не трогает `ANTHROPIC_API_KEY`. Ключ
  Gemini/OpenAI/etc. нужен только для семантической (LLM) экстракции
  doc/paper/image файлов — у нас код-центричный сетап, это не обязательно.

## 2. Первый запуск (пустой клон / графа ещё нет)

Скрипт `graphify-out/update.sh` бутстрапится с нуля сам — не важно, есть уже
`graph.json` или нет:

```bash
bash graphify-out/update.sh
```

Что произойдёт:
1. Найдёт корень репы (`git rev-parse --show-toplevel`) — работает из любого
   клона/воркдира этого проекта без правок путей.
2. Найдёт/установит python-интерпретатор с graphify.
3. По каждому из 6 путей прогонит `graphify update <path>` — это делает
   полную AST-экстракцию с нуля, если графа там ещё не было (никакого
   отдельного шага "инициализация" не нужно).
4. Смёржит все 6 в один граф (`graphify merge-graphs`).
5. Пересчитает community-кластеры глобально, разметит их эвристически (по
   самой частой директории — не LLM, см. пункт 5).
6. Сгенерирует `GRAPH_REPORT.md` (обрезанный до топ-40 коммьюнити) и
   `graph.html`.

Первый прогон занимает ~5 минут (полная AST-экстракция по ~10 тыс. файлов
суммарно на всех 6 путях). Повторные — быстрее за счёт файлового кэша AST.

**Важно для второго клона (например `klone_2/klone-mobile`):** `graphify-out/`
сейчас не закоммичен (там 220+ МБ `graph.json`, коммитить их не стоит). Чтобы
не переносить `update.sh` руками между клонами — можно закоммитить **только
сам скрипт** (без `graph.json`/`graph.html`/кэша), см. пункт 6.

## 3. Настройка — какие пути индексируются

Список путей зашит в начале `update.sh`:

```bash
PATHS=(
  "klone-mobile-server/src"
  "klone-desktop/src"
  "klone/src"
  "server-framework/server/src"
  "server-framework/mobile-fw-server/src"
  "server-framework/server/res"
)
```

Чтобы поменять состав — правишь этот массив руками и перезапускаешь скрипт.
Других путей (`klone-common`, `klone-android/ios/uwp`, тулы) граф не видит —
это осознанное ограничение под личный скоуп работы, не баг.

## 4. Обновление графа

```bash
bash graphify-out/update.sh
```

Гонять после того как код в этих 6 путях заметно поменялся и ты собираешься
реально искать что-то через граф. Жёсткого расписания нет — скрипт дешёвый
(без LLM), но и не бесплатный (~5 минут), гонять на каждый чих/коммит
избыточно. Автоматических git-хуков **нет специально** — штатные
post-commit/checkout/merge хуки graphify сканируют весь репозиторий и были
удалены как бесполезные и затратные для этого кастомного мульти-path сетапа.

## 5. Как этим пользоваться

- **Через Claude Code:** просто задавай вопрос о коде в этих путях — скил
  `/graphify` сам увидит `graphify-out/graph.json` и прогонит
  `graphify query "<вопрос>"` вместо грепа файлов.
- **Руками из терминала:**
  ```bash
  graphify query "как работает WebShop"
  graphify path "GameState" "WebShop"        # путь между двумя узлами
  graphify explain "KloneSession"            # разбор конкретного узла
  ```
- **`GRAPH_REPORT.md`** — только для беглого обзора архитектуры (god-nodes,
  топ-коммьюнити). Не читать построчно — это индекс, а не документация; полный
  список коммьюнити — в `graph.json`.
- Имена коммьюнити — эвристические (по преобладающей директории), не LLM.
  Не удивляйся, если одно и то же имя встречается у десятка разных коммьюнити.

## 6. Опционально: закоммитить только скрипт

Чтобы `update.sh` не нужно было копировать руками между клонами репы:

```bash
# .gitignore — исключить только тяжёлые генерируемые артефакты
echo "graphify-out/graph.json"   >> .gitignore
echo "graphify-out/graph.html"   >> .gitignore
echo "graphify-out/cache/"       >> .gitignore
echo "graphify-out/*/cache/"     >> .gitignore
echo "graphify-out/**/graph.json" >> .gitignore
echo "graphify-out/GRAPH_REPORT.md" >> .gitignore

git add graphify-out/update.sh graphify-out/HOWTO.md .gitignore
git commit -m "..."   # только после явного запроса — не делать автоматически
```

Это не выполнено автоматически — решение коммитить что-либо в репозиторий
принимает пользователь явно.
